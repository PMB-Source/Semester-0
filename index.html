Kolaborasi Tim dengan Git & GitHub

Ikuti panduan ini dari persiapan perangkat, konfigurasi Git, membuat repository bersama, hingga mengirim Pull Request dan mengumpulkan hasil praktikum.

Hands-on practice30–60 menitGit · Git Bash · VS Code · GitHub

Tujuan Praktikum

Setelah menyelesaikan praktikum, setiap peserta diharapkan mampu menggunakan Git untuk mencatat perubahan kode atau dokumen, mengelola branch, mengirim perubahan ke GitHub, serta bekerja bersama anggota tim melalui Pull Request.

Gambaran alur kerja: buat repository di GitHub → undang anggota tim → clone repository → buat branch → ubah file → commit → push → Pull Request → review → merge.

1. Persiapan dan Instalasi

Siapkan komputer atau laptop, koneksi internet, browser, akun GitHub, Git, dan Visual Studio Code. Panduan instalasi berikut ditujukan terutama untuk pengguna Windows.

Instal Git

  1. Buka halaman download Git for Windows melalui tautan di atas.
  2. Unduh installer, lalu jalankan file installer.
  3. Ikuti proses instalasi. Jika belum memahami opsi lanjutan, gunakan pengaturan bawaan installer.
  4. Setelah selesai, buka Start Menu dan cari Git Bash.

Instal Visual Studio Code

  1. Unduh installer dari situs resmi VS Code.
  2. Jalankan installer dan ikuti petunjuknya.
  3. Jika tersedia, aktifkan opsi Add to PATH dan opsi membuka folder dengan VS Code.
  4. Buka VS Code setelah instalasi selesai.
Opsional: Di VS Code, buka tab Extensions dan instal ekstensi GitHub Pull Requests jika ingin mengelola Pull Request dari editor. Praktikum ini tetap dapat diselesaikan melalui browser GitHub.

2. Konfigurasi Git Bash dan Identitas Git

Git Bash adalah terminal untuk menjalankan perintah Git. Buka Git Bash dari Start Menu Windows.

Periksa instalasi

git --version
git --help

Jika versi Git tampil, instalasi berhasil.

Atur nama dan email untuk commit

Gunakan nama dan email yang ingin ditampilkan pada riwayat commit. Sebaiknya gunakan email yang terhubung ke akun GitHub.

git config --global user.name "Nama Lengkap"
git config --global user.email "email-kamu@example.com"

Periksa konfigurasi:

git config --global --list

Apakah harus login GitHub di Git Bash?

Konfigurasi user.name dan user.email di atas adalah identitas pembuat commit, bukan proses login. Untuk autentikasi saat mengirim perubahan ke GitHub, Git Credential Manager biasanya akan membuka browser agar kamu masuk ke akun GitHub dan memberikan otorisasi.

  1. Pastikan kamu sudah login ke GitHub melalui browser.
  2. Saat pertama kali menjalankan perintah git push, ikuti permintaan autentikasi yang muncul.
  3. Jika browser terbuka, login ke akun GitHub yang benar dan setujui otorisasi.
  4. Kembali ke Git Bash setelah proses selesai.
Keamanan: Jangan memasukkan password akun GitHub, Personal Access Token, atau kode autentikasi ke file proyek maupun membagikannya kepada anggota lain. Ikuti jendela autentikasi resmi yang dibuka Git Credential Manager.

4. Mengundang Anggota sebagai Collaborator

Langkah ini dilakukan oleh pemilik repository atau ketua tim yang memiliki hak akses pengaturan repository.

  1. Buka halaman repository yang baru dibuat.
  2. Pilih tab Settings.
  3. Pada menu samping, buka Collaborators atau bagian Collaborators and teams.
  4. Klik Add people.
  5. Masukkan username atau email GitHub anggota tim.
  6. Pilih akun yang benar, lalu kirim undangan.
  7. Minta setiap anggota membuka notifikasi atau email GitHub dan menerima undangan tersebut.
Checkpoint: Pastikan seluruh anggota sudah menerima undangan dan memiliki akses untuk melakukan push ke repository.

5. Clone Repository dan Membuat Branch

Setiap anggota mengerjakan langkah berikut di komputer masing-masing. Ganti URL repository dan nama branch sesuai tim.

Clone repository

Buka Git Bash, pindah ke folder tempat kamu menyimpan proyek, lalu jalankan:

cd ~/Documents
git clone https://github.com/USERNAME/praktikum-kolaborasi.git
cd praktikum-kolaborasi
code .

Perintah code . membuka folder proyek di VS Code. Jika perintah tersebut belum dikenali, buka VS Code secara manual lalu pilih File → Open Folder.

Buat branch pribadi

Setiap anggota wajib memakai nama branch yang berbeda. Gunakan huruf kecil dan hindari spasi.

git switch -c feature/nama-kamu

Contoh:

git switch -c feature/razi

Buat file kontribusi masing-masing

Agar perubahan antaranggota tidak saling menimpa, setiap orang membuat file sendiri di dalam folder anggota. Di VS Code, buat folder anggota, lalu buat file dengan nama masing-masing, misalnya anggota/razi.md.

# Profil Anggota

- Nama: Nama Lengkap
- NIM: NIM Kamu
- Program Studi: Informatika
- Kontribusi: Menjelaskan kontribusi dalam tim

Simpan file tersebut. Pastikan nama file berbeda untuk setiap anggota, misalnya anggota/budi.md dan anggota/siti.md.

Periksa perubahan dan buat commit

git status
git add anggota/nama-kamu.md
git commit -m "feat: add member profile"

Ganti nama-kamu.md sesuai nama file yang dibuat. Commit menyimpan snapshot perubahan ke riwayat Git lokal.

Kirim branch ke GitHub

git push -u origin feature/nama-kamu

Jika diminta autentikasi, ikuti proses login browser seperti pada bagian konfigurasi Git Bash.

Checkpoint: Branch pribadi muncul di GitHub dan file profil milikmu sudah terlihat pada branch tersebut.

6. Membuat Pull Request dan Melakukan Review

Pull Request (PR) digunakan untuk mengusulkan perubahan dari branch pribadi agar dapat digabungkan ke branch utama.

Membuat Pull Request

  1. Buka repository di GitHub.
  2. Pilih tab Pull requests, lalu klik New pull request.
  3. Atur perbandingan branch.
PengaturanPilih
Basemain
Comparefeature/nama-kamu
  1. Pastikan daftar perubahan yang tampil sesuai dengan file yang kamu buat.
  2. Isi judul, misalnya Add member profile - Razi.
  3. Tulis ringkasan singkat, lalu klik Create pull request.

Review oleh anggota lain

  1. Minta minimal satu anggota tim membuka Pull Request tersebut.
  2. Reviewer membuka tab Files changed.
  3. Periksa nama file, isi profil, dan kesesuaian perubahan.
  4. Berikan komentar jika ada yang perlu diperbaiki.
  5. Jika sudah sesuai, reviewer dapat memberikan approval apabila fitur tersebut tersedia dan diizinkan.
Checkpoint: Pull Request sudah dibuat dan diperiksa oleh anggota lain sebelum digabungkan.

7. Merge dan Verifikasi Hasil

Setelah review selesai, ketua tim atau anggota yang diberi wewenang dapat menggabungkan Pull Request.

  1. Buka Pull Request yang sudah direview.
  2. Klik Merge pull request.
  3. Konfirmasi dengan Confirm merge.
  4. Ulangi proses untuk Pull Request anggota lainnya.

Setelah semua PR digabungkan, setiap anggota memperbarui branch utama di komputer masing-masing:

git switch main
git pull origin main
git log --oneline

Buka folder anggota di VS Code atau File Explorer. Pastikan file profil semua anggota sudah tersedia di branch main.
